# yomk 文档编写原则
> 版本：v1.0
> 目标：面向对外发布，**支持分片跳跃阅读**，用户只看自己关心的章节也能读懂；参考 ROS2、spdlog、fmt、Abseil 文档范式，兼顾新手与机器人/中间件开发者；和前面《yomk 注释原则》配套。
> 核心思想：**文档是独立自包含的碎片，不是线性小说；每个章节可以单独打开、单独理解、单独验证；同时全局保持一致的术语、示例、错误提示。**

## 1. 顶层设计原则
1. **分片自包含原则（最重要）**
   任意一个独立章节/子页，**不强制要求用户先读完前面所有章节**。
   - 每个分片自带：简短上下文、必要前提、依赖说明、最小可运行示例、结果说明。
   - 如果依赖其他概念，提供简短一句话摘要 + 跳转链接，而不是“详见第3章”让用户被迫回溯。
   - 禁止埋前置伏笔：不要在后面章节才解释前面用到的关键名词。
2. **分层阅读，按需下沉**
   固定三层结构，所有模块文档统一这个范式：
   - L1：概览（一句话能干什么、适用/不适用场景、快速判断要不要继续看）
   - L2：基础用法（最小示例、常用API、参数含义，80%用户只读到这里就够用）
   - L3：进阶细节（线程模型、内存所有权、阻塞/非阻塞、性能约束、陷阱、自定义扩展）
   用户可以停在任意一层，不需要强制往下读。
3. **双人群友好**
   - 新手：优先看快速上手、示例、可复制代码；减少前置理论轰炸。
   - 资深开发者（ROS2/C++中间件）：可以直接跳“线程模型、生命周期、约束、性能对比”小节。
4. **示例优先，文字补充**
   先给可编译、可运行的最小代码，再解释；不要大段文字描述之后才给示例。
5. **和源码注释分工**
   - 头文件 Doxygen：是 API 参考手册（精确、完整、偏契约）
   - docs 文档：是使用手册（讲场景、为什么、怎么组合API、踩坑）
   > 文档不重复抄Doxygen参数列表；Doxygen 也不写长篇使用教程。

## 2. 页面/分片统一结构规范（每个独立子文档都遵循）
> 每一个分片（比如：上下文查询、日志模块、RPC 请求、链式Builder）都按这个模板组织：
1. **标题 + 一句话摘要**
   一句话回答：这个模块解决什么问题？
2. **适用 & 不适用场景（快速筛选）**
   ✅ 适合：xxx
   ❌ 不适合：xxx
   帮助用户快速判断“这个是不是我要找的”，不合适直接离开。
3. **前置依赖（可选）**
   如果必须的概念，简短说明；附带跳转链接。
   示例：> 本节依赖 yomk 上下文对象；上下文是存放键值配置的全局容器，详见 [Context 概览](./context.md)
4. **最小可运行示例（必选）**
   精简、可直接复制编译，不带无关业务代码。
5. **核心API 简要说明**
   只列出本分片最常用的；完整签名跳转 Doxygen。
6. **典型用法组合（2～3个高频场景）**
7. **约束、安全模型、坑点（重点，机器人中间件用户最关心）**
   - 线程安全
   - 是否阻塞
   - 内存所有权、谁释放
   - 回调限制（回调内能不能再次调用本接口）
   - 异常 / UB 行为
8. **常见问题 FAQ（本分片专属）**
   只放这个模块高频疑问，不要堆全局FAQ。
9. **相关跳转**
   相关模块、扩展方案、对比选型（例如：同步RPC / async RPC / Zenoh桥接）

## 3. 写作风格约定
1. **术语全局唯一**
   所有文档统一术语：不要一处叫“构建器”，另一处叫“链式对象”；和注释、Doxygen 保持一致。
   术语第一次出现时可以附带简短解释，后续直接复用。
2. **区分三种信息，视觉上分开**
   - 正常说明：普通段落
   - 提示 `Note`：最佳实践、小技巧
   - 警告 `Warning`：容易踩坑、UB、生命周期风险、线程问题
   参考 spdlog / ROS2 文档的警告块样式。
3. **少长段落，多短块**
   一个段落只讲一件事；避免大段密集文字。
4. **明确区分“默认行为”和“可配置行为”**
   中间件类库用户非常关心：默认是什么、改哪个参数可以换行为。
5. **对比写法优先**
   选型类文档（Zenoh / DDS / 同步/异步）多用对比：A适合什么，B适合什么，边界清晰。
6. **版本标记**
   新增API、行为变更，标注 `Since: yomk-vX.Y.Z`；废弃功能标注弃用版本、替代方案。

## 4. 导航与跳转规范（实现“跳跃阅读”的关键）
1. 侧边目录：每个页面只展示当前页面内部小标题，全局目录放在首页。
2. 跳转分两类：
   - 内部概念跳转：链接到对应分片文档
   - API 跳转：直接跳 Doxygen 对应函数
3. 避免“顺序式引导”
   ❌ 错误：先阅读【基础概念】，再看【使用示例】
   ✅ 正确：你可以直接复制示例运行；下文会解释里面用到的概念。
4. 首页做“场景化入口”，而不是按章节顺序罗列
   首页入口示例：
   - 快速开始：5分钟跑通 Hello
   - 日志模块：输出日志、文件落盘、异步日志
   - RPC 通信：同步请求 / 异步请求
   - 上下文配置：链式查询 Context
   - 中间件选型：FastDDS / Zenoh 桥接
   - API 参考（Doxygen）
   用户按自己需求点进去，而不是从第一章顺序往下读。

## 5. 示例代码规范
1. 所有示例：完整最小可编译，包含头文件、命名空间、main。
2. 示例附带预期输出/行为说明，用户可以对照验证。
3. 示例标注：`// 注释只解释业务意图，不复述代码动作`，和源码注释原则对齐。
4. 复杂示例拆成多个版本：最简版 → 带参数版 → 进阶定制版。
5. 示例中不要隐藏关键参数、默认行为。

## 6. 禁止清单（红线）
- ❌ 线性叙事：文档设计成必须从前到后阅读
- ❌ 分片缺少自包含信息，到处写“详见xx章节”
- ❌ 大段抄写Doxygen参数列表，重复冗余
- ❌ 隐藏约束：线程安全、阻塞、内存所有权埋在很深的章节
- ❌ 示例不可直接复制运行（缺头文件、缺命名空间、隐式依赖）
- ❌ 术语漂移，同一概念多个叫法
- ❌ 只讲“能做什么”，不讲“什么时候不该用”

## 7. 配套目录结构建议（给你参考）
```
docs/
├── README.md                # 文档首页，场景化入口
├── getting_started/
│   └── quickstart.md        # 快速上手
├── modules/                 # 各个独立分片（核心）
│   ├── logger.md
│   ├── context.md
│   ├── rpc.md
│   ├── builder_api.md
│   └── middleware_bridge.md
├── guides/
│   ├── thread_safety.md
│   ├── memory_model.md
│   └── build_cmake.md
├── faq/
│   └── general_faq.md
├── references/
│   └── doxygen 跳转入口
└── contributing/
    └── yomk_comment_rule.md  # 你之前那份注释规范
```

## 8. 一句话总结
> 每一页文档都可以当成独立手册；用户带着目标进来，只看这一页就能完成他当下的任务；需要更深信息时，再顺着链接向下/向旁跳转。
