# YomkMsg（消息与类型系统）

业务数据的安全封装与传递：消息类**继承 `YomkMsg` 即接入标准类型系统**——免费获得运行期类型名 `TYPE_NAME`，端点声明、精确校验、错误文案统一消费它，全程零手写报文名。实例直接作为请求负载传入功能函数、经回包 `data` 原样返回，属性直接访问，无序列化封套、无指针封送。

## 核心概念：类型名（`TYPE_NAME`）

`TYPE_NAME` 是挂在消息类上的运行期类型名（类常量），**继承即得，禁止手写**，生成后**只读**：

- 命名按 Python 类常量惯例：全大写下划线，不带 C++ 风格的 `k` 前缀；
- 自动生成规则（规则 B）：**最近一级父包 + "." + 类限定名**。如 `yomk.msgs.ctx` 包里的 `Context` → `"yomk.msgs.ctx.Context"`；std 类定义于 `yomk.msgs.std_msg` → `"yomk.msgs.String"`；
- 顶层模块（无父包，如直接运行的脚本）回退用完整 `__module__`：`"__main__.Foo"`；
- 随类重命名自动跟随；**类体显式定义 `TYPE_NAME` 直接 `TypeError`**（`TYPE_NAME is generated by YomkMsg, do not define it in the class body`），对齐 C++ 只能经 `YOMK_DEFINE_MSG` 生成的口径；
- 生成后即**只读常量**：类上重绑定/删除、实例上赋值/删除一律 `AttributeError`（`TYPE_NAME is a read-only class constant`），对齐 C++ `static constexpr`——实例层无法遮蔽类型名；
- 值口径与 C++ 一致：main 分支根级宏同样带 `yomk::msgs::` 前缀，全库无裸名；
- 基类 `YomkMsg.TYPE_NAME` 为空串，基类实例不可作载荷（`require_msg_instance` 拒绝）。

## 载荷契约（跨边界一律消息实例）

框架的类型边界只有一种载荷形态：**具体 `YomkMsg` 子类实例，或 `None`（空载荷）**。裸值、`dict`/`list`、体系外自定义类、`YomkMsg` 直接基类实例均不允许：

| 边界 | 入口 | 违例行为 |
|---|---|---|
| 服务请求 | `server().url(u).msg(msg)` | `TypeError: msg() requires a YomkMsg instance, got 'str'` |
| 服务侧调用 | `self.request(url, msg)` / `install_func` 装载端点的请求 | 同上（`request()` 入口） |
| 函数池调用 | `fn_pool().fn_name(n).msg(msg).call()` | 同上（`msg()` 入口） |
| 事件循环投递 | `event_loop().msg(msg)` / `Event(..., msg, ...)` | 同上 |
| 上下文值 | `ctx().key(k).value(msg).create()/.set()` | `TypeError: value() requires a YomkMsg instance, got 'str'` |
| 上下文兜底 | `ctx().key(k).msg(cls).with_default(msg)` | 裸值：`TypeError: with_default requires a YomkMsg instance, got 'str'`；消息但类型不符：`TypeError: with_default requires '<cls.TYPE_NAME>' or None, got '<其他 TYPE_NAME>'` |

分类口径：入口类型契约违例一律 `TypeError`（调用方编程错误，当场炸出并归因到行）；got 侧由 `unpack` / `require_*` 内部生成——消息报 `TYPE_NAME`、`None` 报 `"null"`、类对象报其类名（如 `"String"`）、其余对象报宿主类名（如 `"str"`）。`ResStatus` 只表运行期业务失败。跨边界收到的消息包类型不符期望时，端点返回 `Failed/eNo` + `r.error` 文案，不抛异常。

## API 速查

| 操作 | Python 形态 |
|---|---|
| 定义消息 | `class MyMsg(YomkMsg):` + 构造函数即字段声明 |
| 标准标量/数组 | `String` / `Bool` / `Int` / `Float` / `Bytes`（字段 `value`）；`BoolArray` / `IntArray` / `FloatArray` / `StringArray`（字段 `items`） |
| 结构化清单 | 各域 List msg（如 `ContextKeyInfoList`、`FuncInfoList`，字段 `items`） |
| 端点声明 | `self.install_func("/x", self.x, MyMsg.TYPE_NAME)` |
| 端点体校验 | `r = unpack(msg, MyMsg)` → `if not r: return Response(eNo, r.error)`，命中字段取 `r.msg.<field>` |
| 调用方解包返回 | `unpack(res.data, MyMsg)` → `UnpackResult`：判真取 `r.msg`、判假取 `r.error` |
| 请求负载 | `server().url(u).msg(MyMsg(...)).request()` |

## 标准内置集（std 类）

C++ 30 个 std msg 收敛直译为 9 类（定义于 `yomk.msgs.std_msg`，`from yomk.msgs import ...`）：

| std 类 | 承载 | 收敛的 C++ 类型 |
|---|---|---|
| `Bool` / `Int` / `Float` / `String` / `Bytes` | 标量（字段 `value`） | 11 个整型/字符变体 → `Int`；Float32/64 → `Float`；`Bytes` 为 Python 端新增 |
| `BoolArray` / `IntArray` / `FloatArray` / `StringArray` | 列表（字段 `items`） | 15 个 `*Array` 收敛 |

Python 的 `int` / `float` 不区分位宽，故标量类名为 `Int` / `Float`，不带 C++ 的 `64` 后缀；C++ 侧仍是 `Int64` / `Float64`，两侧 `TYPE_NAME` 不同，跨语言共享时需单独映射。

## 端点标准形态（必须遵守）

三条消费规则，框架服务与用户服务同规（可抄范本见 `template/extension/src/yomk/extension/ExtensionService.py`、`template/project/services/ConfigService.py`）：

1. **端点声明**：第三参一律传 `msg.TYPE_NAME`，**禁止手写字面量**——TYPE_NAME 随类定义自动生成、随重命名跟随，手写串与内省值漂移即失真；
2. **端点体内精确校验**（框架不做分发校验，责任在端点作者）：

```python
def echo(self, msg):
    r = unpack(msg, ExtensionRequest)
    if not r:
        return Response(ResStatus.eNo, r.error)
    ...   # 下游一律 r.msg.<field>
```

3. **调用方构造**：载荷是消息类实例，裸值直发会被精确身份校验拒绝。

## unpack 语义（返回 `UnpackResult`）

`unpack(msg, cls)`（对齐 C++ `unpack<Msg>` → `UnpackResult<Msg>`）：解包结果是一个只读结果对象，**判真取 `r.msg`、判假取 `r.error`**，调用方不再手传期望类型名：

- **命中 ⟺ `type(msg)` 就是 cls 本身**（具体消息实例 + TYPE_NAME 精确比对）——不是普通 isinstance 兼容判断：子类必然获得与父类不同的自动 TYPE_NAME，**子类实例解包为父类返回判假结果是设计行为**；
- `msg` 为 `None`、体系外对象或类型不符 → 结果**判假**（`r.msg is None`），文案已生成在 `r.error`，不抛异常（端点据此直接拒绝）；
- `cls` 必须是具体 `YomkMsg` 子类（不能是基类本身或体系外类）→ 违例抛 `TypeError`（`unpack requires a concrete YomkMsg subclass, got '<类名>'`），调用方编程错误不当成业务失败；cls 守卫先于命中判断，故 `unpack(None, None)` 也抛 `TypeError`。

`is_msg_instance(v)` / `is_msg_subclass(cls)`（同置 `yomk.msgs.YomkMsg`）：一对形态判据。`is_msg_instance` 判**实例**——仅具体 `YomkMsg` 子类实例为真，`None`（空载荷）、`YomkMsg` 直基类实例、类对象与体系外对象均为假，`None` 的合法性由调用方自行判定，由 `require_msg_instance` / `unpack` / 诊断文案共用；`is_msg_subclass` 判**类域**——只认具体消息子类（类对象本身），基类、非类与体系外类均为假，由 `require_msg_subclass` 与 `unpack` 共用。两处判据不再分散书写。

守卫侧成对提供：`require_msg_instance(v, who)` 守实例入口（仅具体实例，违例 `TypeError`；`None` 不是实例，空载荷由调用方先判 `is not None` 再调用），`require_msg_subclass(cls, who)` 守类域（具体消息子类，违例 `TypeError`）；`unpack` 的 cls 守卫与 `ctx().key(k).msg(cls)` 均经后者，文案统一为 `"<who> requires a concrete YomkMsg subclass, got '<类名>'"`。

`class UnpackResult`（与基类/解包/守卫同置 `yomk.msgs.YomkMsg`，`yomk.msgs` 顶层导出）：

- `bool(r)`：命中为 `True`（`r.msg` 非 `None`），未命中为 `False`——端点统一写 `if not r:`；
- `r.msg`：命中时为传入实例本身（同一对象，非拷贝）；未命中为 `None`；
- `r.error`：命中为空串；未命中为标准文案 `"msg is not <cls.TYPE_NAME>, got '<actual>'"`，期望侧取自 `cls.TYPE_NAME`，实际侧四态取值（消息实例 → `TYPE_NAME`；`None` → `"null"`；类对象 → 类名；其余 → 宿主类名）在 `unpack` 内联生成，用户侧需要类型名时直连只读 `TYPE_NAME`；
- 出口只读：`r.msg = ...` / `r.error = ...` 抛 `AttributeError`（对齐 C++ 只读出口）；`repr` 命中带 msg、未命中带 error。

## 完整示例（定义 → 声明 → 端点校验 → 调用）

```python
from yomk.msgs import YomkMsg
from yomk.server import YomkService
from yomk.msgs.server import ResStatus, Response
from yomk.msgs.YomkMsg import unpack

# 1. 定义（继承即得 TYPE_NAME）
class UserInfo(YomkMsg):
    def __init__(self, uid, name):
        self.uid = uid
        self.name = name

class RegisterResp(YomkMsg):
    def __init__(self, uid, greeting):
        self.uid = uid
        self.greeting = greeting

class UserService(YomkService):
    def init(self):
        # 2. 声明（传 TYPE_NAME，禁止手写）
        self.install_func("/register", self.register, UserInfo.TYPE_NAME)
        return 0

    # 3. 端点体精确校验（责任在端点作者）
    def register(self, msg):
        r = unpack(msg, UserInfo)
        if not r:
            return Response(ResStatus.eNo, r.error)
        return Response(ResStatus.eOk, "hello",
                        RegisterResp(r.msg.uid, "hello " + r.msg.name))

# 4. 调用方构造与解包
res = server().url("/UserService/register").msg(UserInfo(1001, "Alice")).request()
rsp = unpack(res.data, RegisterResp)      # 判真取 rsp.msg、判假取 rsp.error
```

## 语言设计说明

- 无需宏/工厂/指针基类流转：继承一个基类即完整接入，对象引用直传；
- 类型不符不会静默：守约则全检，失约（忘写 unpack）在首次字段访问即以 AttributeError + 堆栈响亮炸出、归因到行——责任分明是设计目标；
- 跨边界载荷只有一种合法形态：具体消息实例或 `None`。裸值、`dict`/`list`、体系外自定义类、`YomkMsg` 直接基类实例在入口当场 `TypeError`（见上文"载荷契约"），不存在静默降级路径；响应 `data` 侧仍可按需承载非消息结果。

## 注意事项

- **声明与内省**：`install_func` 第三参、`fn_pool().msg_name(m)`、`event_loop().msg_name(m)` 的值存入 `FuncInfo.msg_name` 供内省读取（值为全限定 TYPE_NAME），运行期不做拦截（责任模型见上）。
- 上下文类型化读 `ctx().key(k).msg(cls).with_default(d).get()`：`cls` 必填且须为具体消息类（省略或传体系外类 → `TypeError`）；`d` 必须是同 `TYPE_NAME` 的消息实例或 `None`（违例 → `TypeError`）。`get()` 按 TYPE_NAME 比对，不符记 WARN 并回退 `d`。
- 事件循环 `post_wait` 的执行结果经事件对象回传：链式终结收敛为 `ResStatus`；需要取回事件 `data`/处理响应时用裸链 `server().url("/YomkEventLoop/post_wait").msg(...).request()`，`data` 为该 `Event` 对象（含 `m_eventId` / `m_response`）。
- 内省端点返回 List msg（如 `/all` 返 `FuncInfoList`），链式门面读路径已解包、仍返回裸 list；裸链直调时先 `r = unpack(res.data, XxxList)`，再取 `r.msg.items`（判假取 `r.error`）。
