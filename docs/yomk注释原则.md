# yomk 注释原则
> 版本：v1.0
> 定位：对外公开API 对齐 ROS2 / FastDDS / CycloneDDS 文档风格；内部实现对齐 STL 极简思想，仅保留关键注释。
> 核心思想：**对外注释面向使用者，讲清能力与约束；内部注释面向维护者，只写代码无法表达的前提、不变量与特殊取舍。**

## 1. 适用划分
- **规则A（Doxygen 文档注释）**：`.hpp` / `.h` 中对外导出、public 接口、Builder 类、消息类型、枚举、模块入口。
- **规则B（STL 极简注释）**：`.cpp` 实现、private 成员、内部 helper、匿名命名空间、内部结构体、实现细节。

> 一句话判断：别人会调用的 API → 规则A；只在框架内部调用、使用者看不到的代码 → 规则B。

## 2. 规则A：对外公开API注释规范
### 2.1 基本原则
1. 注释写给**调用方**，描述接口能力、约束、风险，**不解释内部实现逻辑**。
2. 使用 Doxygen 块注释 `/** */`，放置在类/函数/枚举上方。
3. 禁止复述代码语义，不要写和函数名、参数名重复的废话。
4. 机器人中间件重点信息必须按需标注：线程安全、是否阻塞、内存所有权、回调约束、异常行为、未定义行为。
5. 模板接口、链式 Builder 额外补充类型约束、调用顺序约束。
6. 废弃接口使用 `@deprecated`，标注替代方案。

### 2.2 可用标签（按需选用，禁止堆砌）
- `@brief`：一句话概要（**必选**）
- `@param[in] / @param[out] / @param[in,out]`：参数说明
- `@return`：返回值含义，特殊返回场景（空/失败）说明
- `@note`：重要特性、使用说明
- `@warning`：高危约束、常见踩坑点
- `@pre`：前置条件，不满足将产生未定义行为
- `@tparam`：模板参数约束
- `@deprecated`：废弃接口，推荐新接口

### 2.3 对外示例
```cpp
/**
 * @brief 读取上下文配置项
 * @param key 配置键名
 * @param default_val 键不存在时返回的兜底值
 * @return 配置字符串
 * @note 线程安全，非阻塞
 * @warning 传入空key不会报错，但不会匹配任何配置
 */
std::string get(const std::string& key, const std::string& default_val);

/**
 * @brief 上下文配置查询构建器
 * 链式构造查询条件，调用 get() 终止并执行查询
 */
class ContextQueryBuilder
{
public:
    /**
     * @brief 指定查询键名
     * @param key 目标键
     * @return 自身链式引用
     */
    ContextQueryBuilder& key(std::string key);

    /**
     * @brief 终止链式调用，执行查询并返回结果
     */
    std::string get();
};
```

## 3. 规则B：内部源码注释规范（对齐 STL）
### 3.1 基本原则
> 优先依靠命名、类型、常量、结构表达逻辑；**无特殊约束就不写注释**。
> 注释仅用于记录代码无法直观表达的信息。

1. 仅使用单行注释 `// `，`//` 后保留一个空格；**内部代码禁止写 Doxygen 块注释**。
2. 仅在以下场景写注释：
   - 前置条件（Precondition）：调用前必须满足的前提，否则 UB
   - 不变量（invariant）：对象/数据结构始终维持的约束
   - 算法复杂度、性能取舍
   - 反直觉写法、特殊兼容 workaround
   - 已知边界缺陷、临时限制
3. 禁止注释描述循环、分支、赋值等普通执行动作；不写“遍历列表”“累加计数”这类复述代码的注释。
4. 内部 helper、私有函数、局部变量默认不加注释。

### 3.2 内部示例
```cpp
// Precondition: buf != nullptr, buf->size() < max_capacity
static void append_frame(Buffer* buf, std::string_view payload)
{
    // invariant: write_pos <= capacity
    // 环形覆盖策略，队列满时直接丢弃旧数据，不阻塞生产者
}
```

❌ 禁止内部出现这类注释：
```cpp
// 遍历所有sink，写入日志
for (auto& sink : sinks_) {
    sink->write(msg);
}
```

## 4. 链式API（Builder）专项约定
yomk 大量使用链式 Builder 风格，单独约定：
1. Builder 类本体：规则A，注释说明整体用途、终止函数、调用约束。
2. 链式中间方法（`.key()` `.type()` `.default()`）：简短Doxygen，说明作用 + 返回自身以支持链式调用。
3. 终止函数（`.get()` / `.emit()` / `.request()`）：重点标注阻塞性、线程安全、返回值、生命周期约束。
4. Builder 内部状态、私有成员：规则B，仅写不变量与前置条件。

## 5. 全局格式统一约定
1. 对外文档注释：`/** */`，内部说明注释：`// `；项目内不混用 `///` 文档注释。
2. 注释内标点统一使用英文标点。
3. 文档唯一来源：头文件 public 接口；`.cpp` 实现中不写Doxygen文档。
4. 注释同步原则：代码变更后，过时注释优先直接删除，不要保留过期注释。
5. 禁止用注释弥补糟糕命名；命名优先于注释。

## 6. 红线禁止清单
- ❌ 在 cpp 实现里写 Doxygen 文档注释
- ❌ 内部实现大量堆砌注释
- ❌ 注释内容和代码动作完全重复
- ❌ 保留过期、和代码不一致的注释
- ❌ 依靠注释掩盖模糊、难懂的命名

## 7. 快速检索口诀
> 对外头文件API：写清能力、约束、坑点（ROS2 风格）
> 内部实现源码：无前置、无不变量、无特殊取舍 → 不写注释（STL 风格）
